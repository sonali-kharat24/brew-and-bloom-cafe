# Brew & Bloom — Café Website (Concept Project)

A fictional specialty café website built as a frontend portfolio piece. **Brew & Bloom is not a real business.**

## Concept
A warm, editorial-style site for a neighbourhood café: hero, story, filterable menu, best sellers, gallery with lightbox, visit info and a reservation form.

## Design decisions
- **Palette:** cream `#F4EBDD`, coffee brown `#49352A`, white, sage `#A5A77B`, espresso `#241B17`. Light and dark sections alternate for rhythm. Sage is only used as text on dark backgrounds; a darker sage is used on cream for readable contrast.
- **Type:** Fraunces (expressive serif headlines) + DM Sans (body), loaded from Google Fonts with Georgia / system fallbacks.
- **Hero:** split editorial layout with an arched image frame, offset outline and a ticker of café keywords.
- **Menu:** grouped into Coffee / Cold Beverages / Bakery headings like a printed menu board; filters show one group.
- **Best sellers:** alternating image/text rows with large italic numerals.
- **Shapes:** small corner radii and arch-shaped images instead of generic rounded cards.
- **Motion:** gentle fade-up on scroll, hover zooms, smooth scrolling. All disabled for users who prefer reduced motion.
- **Imagery:** original illustrations (SVG) generated by `tools/make-art.mjs`. They are not photographs. See "Swapping in photos" below.

## Technologies actually used
Plain **HTML, CSS and JavaScript**. No framework, no build step, no dependencies.

## Features
Responsive layout (desktop/tablet/mobile) · working mobile menu · scroll-spy nav · working menu category filters · lightbox gallery (keyboard: ← → Esc) · accessible form with validation · skip link, semantic landmarks, focus styles.

## Run it
- Quick: open `index.html` in a browser.
- Recommended (local server): `python3 -m http.server 8000` in this folder, then visit http://localhost:8000.

## Connecting real reservations
The form is an honest **demo**: it validates, then says nothing was sent or booked. To go live:
1. Create a form endpoint (e.g. Formspree, Basin, or your own backend / a reservation service such as a booking platform).
2. Paste its URL into `formEndpoint` in `js/data.js`. The form then POSTs JSON and only shows success if the service replies OK.
3. For real bookings you also need availability rules, confirmation emails and spam protection (e.g. a CAPTCHA) on the service side.

## Swapping in photos
Put licensed photos in `assets/`, then change the `image` file names in `js/data.js` (and the `hero.svg` / `story-*.svg` / `g-seating.svg` paths in `index.html`). Update the `alt` text to describe the photo. Check each photo's licence (e.g. Unsplash, Pexels) before publishing.

## Deploy (free) with GitHub + Vercel
1. Put this whole folder in a new GitHub repository (the file `index.html` must be at the top level).
2. On vercel.com choose **Add New > Project**, import the repository, set **Framework Preset** to **Other**, leave Build Command and Output Directory empty, and click **Deploy**.
3. Every time you push a change to GitHub, Vercel republishes the site automatically.
